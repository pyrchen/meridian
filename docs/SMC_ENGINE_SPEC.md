# Спека: SMC-слой рядом с v3-focus

> Статус: **черновик, раздел 6 (правила SMC) заполняется из разбора видеокурса.**
> Источник правил — `docs/knowledge/sancho-smc/` (51 транскрипт канала @SanchoDT, 13.6 ч).
> Движок-основание — `scripts/gen-signals.mjs` (`ENGINE = 'v3-focus'`).

## 1. Зачем

v3-focus вышел на честное плато: `avgNetR +0.046`, WR ~32%, 90% CI `[−0.05, +0.15]`.
Плато достигнуто выжиманием **фильтров входа** (ADX-гейт, подавление срезов, потолок RR).
Всё, что можно было отжать перебором порогов, уже отжато — дальнейший свип порогов даёт
только оверфит (зафиксировано в `docs/SIGNAL_REDESIGN_PLAN.md`).

Незанятый резерв лежит не в фильтрах, а в **исполнении**:

| Что делает v3-focus сейчас | Чего он не делает |
|---|---|
| Вход по `close` сигнальной свечи, вслепую | Не ждёт отката к зоне интереса |
| Стоп = `1.8 × ATR` от входа, всегда | Не ставит стоп за структуру |
| Цель = `RR_CAP 2.5 × риск`, всегда | Не тянет цель до ближайшего пула ликвидности |
| RR фиксирован независимо от контекста | Не отказывается от сделки без структурного основания |

Гипотеза: сигнал v3-focus — это **хорошее плато для рассмотрения позиции**, но сырая точка
входа. Тот же сигнал, взятый по SMC-правилам (после снятия ликвидности, из ордер-блока,
в зоне дискаунта), даёт лучший R при той же цели — либо отменяется как структурно
необоснованный.

## 2. Что именно строим

Два независимо измеряемых потребителя одного набора примитивов:

**A. Рефайнер** — постпроцессор над готовым сигналом v3-focus. Четыре исхода:

| Исход | Смысл | Эффект на сделку |
|---|---|---|
| `pass` | структура согласна, входим как есть | сделка v3-focus без изменений |
| `improve` | структура даёт лучший стоп/цель | тот же вход, стоп за структуру, цель до пула ликвидности → выше RR |
| `defer` | вход преждевременен | лимитный ордер в зону (OB / FVG / OTE) с TTL и уровнем инвалидации |
| `veto` | структурного основания нет | сделка не берётся |

**B. Генератор** — самостоятельный поиск сигналов по SMC, без опоры на индикаторный скор
v3-focus. Отдельный поток, отдельная книга, отдельные метрики. Никогда не смешивается
с потоком A в одной цифре.

## 3. Инварианты (нарушение = отклонение реализации)

1. **v3-focus по умолчанию не меняется.** Весь SMC-слой за env-флагом `SMC_MODE`
   (`off` | `refine` | `generate` | `both`), по умолчанию `off`. Без флага реплей обязан
   давать **бит-в-бит** тот же `trades.json`, что и сейчас. Это проверяемое условие приёмки,
   а не пожелание.
2. **`scripts/smc.mjs` — чистый модуль.** Ни `fetch`, ни файлового IO, ни `process.exit`,
   ни `Date.now()`. Только функции над массивами свечей. Тот же инвариант P0-1, что и у
   `gen-signals.mjs`, — иначе харнес не сможет вызвать его AS-OF.
3. **Никакого заглядывания вперёд.** Любая функция принимает окно свечей, уже обрезанное
   по `ct <= T`. Решение о входе не может зависеть ни от одной свечи с `ct > T`.
   Существующие счётчики аудита (`windowChecks`) расширяются на SMC-вызовы.
4. **Отложенный вход — не читерство.** Заполнение лимитника использует будущие свечи, и это
   легитимно ровно в той же мере, в какой `evaluateSignal` использует их для определения
   исхода. Но: цена заполнения = **уровень лимитника**, не `close` и не `low` свечи;
   касание определяется по `low <= level <= high`; при касании стопа и лимитника в одной
   свече считаем **сначала лимитник, затем стоп** только если `low < level` строго —
   иначе сделка не открывается (консервативно).
5. **Стоимость сделки не меняется.** `tradeCostPct` применяется как есть. Отложенный вход
   лимитником в реальности дал бы мейкерскую комиссию вместо тейкерской, то есть мы
   **завышаем** издержки. Оставляем завышение — консервативно.
6. **Отменённые сигналы считаются.** См. раздел 5: без учёта отменённых любое сравнение
   средних бессмысленно.

## 4. Расширение харнеса: отложенные входы

`backtest.mjs` сейчас входит немедленно по `close` сигнальной свечи. Для `defer` нужен
модельный лимитный ордер.

```
для сигнала с pending = { limit, expiryBars, invalidate }:
  сканируем свечи idx+1 .. idx+expiryBars:
    если сторона long:
      если k.l <= invalidate            → CANCELLED_INVALIDATED  (структура сломана до входа)
      если k.l <= limit                 → FILLED по цене limit в момент k.ct
    (для short зеркально по k.h)
  если дошли до expiryBars без касания  → CANCELLED_EXPIRED
```

Порядок проверок внутри свечи: **инвалидация раньше заполнения**. Внутрисвечной
последовательности мы не знаем, поэтому берём худший для нас вариант.

После заполнения сделка живёт по обычным правилам `evaluateSignal`, но:
- `createdAt` = момент заполнения (не момент сигнала) — иначе `MAX_AGE_DAYS` считается неверно;
- `entry` = `limit`;
- `sl` / `tp` — **абсолютные структурные уровни** из решения рефайнера, а не пересчёт от ATR.
  В этом весь смысл: стоп за структуру, а не за волатильность.

Срок жизни отложенного ордера вычитается из срока жизни сделки: `expiryBars` тратится
из бюджета `MAX_AGE_DAYS[horizon]`, а не добавляется к нему.

## 5. Протокол измерения (главный раздел)

Наивное сравнение «avgNetR базы против avgNetR SMC» **невалидно**: слой, который отменяет
90% сигналов и берёт лучшие 10%, покажет прекрасный средний R и почти нулевую суммарную
прибыль. Поэтому измеряем по-другому.

Базовый реплей уже знает исход **каждого** сигнала. Значит, для отменённых сигналов
известен контрфактический результат — что было бы, если бы мы их взяли. Это делает
оценку строгой.

Каждый сигнал базы получает **диспозицию**:

| Диспозиция | Что произошло | Что меряем |
|---|---|---|
| `taken_as_is` | `pass` | netR факт |
| `taken_improved` | `improve` | netR факт **и** netR базы на том же сигнале — дельта |
| `taken_deferred` | `defer`, лимитник заполнен | netR факт **и** netR базы — дельта |
| `skipped_unfilled` | `defer`, не заполнен | netR базы (упущенное) |
| `skipped_veto` | `veto` | netR базы (**избежанное**) |

Отчёт обязан содержать:

1. **Избежанный убыток** — сумма `netR` базы по `skipped_veto`. Отрицательна → вето полезно.
   Положительна → вето режет прибыль, слой вреден независимо от красоты средних.
2. **Упущенная прибыль** — то же по `skipped_unfilled`.
3. **Дельта на пересечении** — по сигналам, взятым обоими движками: `Σ netR(SMC) − Σ netR(база)`.
   Это чистый вклад улучшенных стопов/целей, свободный от эффекта отбора.
4. **Суммарный netPnl обоих потоков** — при равном стартовом капитале и равном риске на сделку.
5. **Число сделок** обоих потоков. Падение потока более чем вдвое отмечается явно:
   меньше сделок = шире доверительный интервал, а не «лучше стратегия».

Плюс отдельно и не смешиваясь — поток генератора (B): сигналы, которых у базы не было.

### 5.1 Как обеспечить парность сравнения

Наивная схема «прогнать базу, прогнать SMC, сматчить по id» **сломается**. Причина:
блокировка ключа `symbol|side|horizon` держится до закрытия позиции. Если SMC наложил
вето, позиция не открывается, ключ свободен — и на следующем баре появится сигнал,
которого у базы не было (она в этот момент сидела в сделке). Потоки разъедутся, и разница
в результатах будет объясняться не качеством решений, а дрейфом состава.

Поэтому оба исхода считаются **в одном прогоне**:

```
для каждого кандидата, выданного analyzeHorizon:
  baseOutcome = evaluateSignal(candidate, ...)        // всегда, независимо от решения
  decision    = smcRefine(candidate, ctx)
  smcOutcome  = (решение != veto и лимитник заполнен) ? evaluateSignal(модифицированный, ...) : null
  записать { signalT, symbol, side, horizon, disposition, baseNetR, smcNetR, ... }
  блокировать ключ по closedAt БАЗОВОГО исхода          // ← ключевой момент
```

Блокировка ведётся по базовому исходу, а не по SMC-исходу. Тогда набор сигналов в обоих
потоках **идентичен по построению**, и любая разница результатов вызвана только решением
слоя. Проверяется тривиально: число записей должно совпасть с 3352 базового реплея.

**Осознанное занижение.** В реальности отменённая сделка освобождает капитал, и он мог бы
уйти в другую позицию. Наша схема эту выгоду не засчитывает. Занижение в пользу базы —
принимаем, так честнее.

### 5.3 Обязательная контрольная группа — иначе вердикт будет ложным

Замер на базовой книге (`scripts/smc-legacy-check.mjs` и разбор MAE) вскрыл конфаундер,
который сам по себе способен произвести фальшивое «SMC работает».

Распределение просадки против сделки (`maeR`) на 3187 решённых сделках:

| | медиана | p75 | p90 |
|---|---|---|---|
| выигравшие (n=1062) | 0.37 R | 0.63 R | 0.84 R |
| проигравшие (n=2125) | 1.17 R | — | — |

Выигрыши почти не подходят к стопу, проигрыши пробивают его насквозь. Значит **сужение
стопа улучшает ожидание само по себе**, безотносительно того, ставится он «по структуре»
или просто уменьшением множителя ATR:

| Стоп от текущего | Потеряно выигрышей | Расчётный avgNetR |
|---|---|---|
| 100% (база) | — | +0.093 |
| 90% | 5.0% | ≈ +0.117 |
| 80% | 12.1% | ≈ +0.118 |
| 70% | 18.9% | ≈ +0.130 |
| 50% | 34.6% | ≈ +0.162 |

**Контроль выполнен, и он опроверг наивную оценку.** `ATR_MULT_OVERRIDE=1.4`,
тег `ctl14`, та же вселенная и окно:

| Прогон | n | WR | avgNetR | Σ netPnl |
|---|---|---|---|---|
| база (`ATR_MULT` 1.8) | 3187 | 33.3% | **+0.093** | **+1219%** |
| контроль (`ATR_MULT` 1.4) | 3693 | 33.2% | +0.070 | +723% |

Сужение стопа сделало **хуже**. Причины, обе структурные:

1. Движок задаёт цель как `rr × slDist`. Сужая стоп, он сжимает **и цель** — R остаётся
   2.5, геометрия не меняется. Это не «тот же тейк при более близком стопе», а вся сделка
   в масштабе. При этом издержки (`FEE_RT + SLIP_RT`) фиксированы в процентах цены, поэтому
   в долях R они растут — отсюда падение avgNetR при почти неизменном винрейте.
2. Гейт `SCALP_RISK_PCT_MAX = 4.5` пропустил 506 дополнительных сделок, ранее отсеянных
   как «цель недостижима за срок жизни». Они и разбавили книгу.

**Что из этого следует.** Анализ MAE остаётся верным: запас между входом и стопом у
выигрышей действительно избыточен. Но забрать этот запас можно **только** сузив стоп
**при сохранении цены цели** — то есть ровно тем, что делает структурный стоп и чего
множитель ATR сделать не может в принципе. Дешёвой альтернативы SMC-слою здесь нет:
она проверена и отвергнута измерением.

**Второй контроль выполнен** (`ctl14rr`): стоп 1.4×ATR при `RR 3.214`, то есть цена цели
в точности прежняя. Это самая честная проверка идеи «забрать избыточный запас до стопа».

| Прогон | n | WR | avgNetR | Σ netPnl |
|---|---|---|---|---|
| база (`ATR 1.8`, `RR 2.5`) | 3187 | 33.3% | **+0.0926** | **+1219%** |
| `ctl14` (`ATR 1.4`, `RR 2.5`) | 3693 | 33.2% | +0.0699 | +723% |
| `ctl14rr` (`ATR 1.4`, `RR 3.214`) | 3476 | 27.8% | +0.0804 | +738% |

Проигрывает и он. Разбор, почему:

- валовый avgR **вырос**: `0.333×2.5 − 0.667 = 0.166` → `0.278×3.214 − 0.722 = 0.172`;
- но винрейт упал с 33.3% до 27.8% — узкий стоп выбил больше выигрышей, чем следовало
  из распределения MAE;
- и главное: `FEE_RT + SLIP_RT` фиксированы в **процентах цены**, а `riskPct` сжался на 22% —
  значит издержки в долях R выросли на те же ~28%, съев весь валовый прирост и ещё немного.

**Вывод, который меняет постановку задачи.** Избыточный запас до стопа существует, но
транзакционные издержки не дают его забрать перестановкой уровней. Следовательно, SMC-слой
не может выиграть геометрией. Выиграть он может только двумя способами:

1. **отбором** — вето на сделки, которые база берёт зря (тогда растёт Σ netR при падении n);
2. **ценой входа** — `defer` даёт лучший фактический fill, что увеличивает R **без** сужения
   стопа в процентах цены, а значит без роста издержек в долях R.

Именно эти два канала и надо мерить раздельно в отчёте по разделу 5. Если весь выигрыш
слоя окажется в `improve` (перестановка уровней) — это будет тот же эффект, что уже
дважды отвергнут контролями, и засчитывать его нельзя.

**Оговорка к контролям.** В обоих число сделок выше базового (3693 и 3476 против 3187):
сужение стопа уменьшает `riskPct`, и гейт `SCALP_RISK_PCT_MAX = 4.5` пропускает сделки,
ранее отсеянные. Сравнение поэтому не идеально парное. Направление, однако, однозначно:
оба контроля хуже базы и по среднему, и по сумме.

### 6.0 Главный риск спеки — прочесть до реализации

Разбор курса вскрыл проблему, которую нельзя замолчать: **у автора нет одного
детерминированного определения свинг-точки.**

- В части 1 курса он даёт шаблон на 3 и 5 свечей, но тут же говорит, что лично размечает
  свинги **«визуально, не считая свечей»** (`H-structure-course.md`, часть 1 `[03:52]`).
- В части 2 определение расходится натрое: (1) только по телам; (2) свинг по теням, слом по
  закрытию тела; (3) и свинг, и слом по теням — последний вариант автор называет своим
  предпочтительным.
- Для «равных максимумов» числового допуска нет. Для соотношения импульс/коррекция порога нет.
- Современный ролик 2025 года («Структура рынка за 29 минут») даёт чистые 3- и 5-свечные
  правила — на них и опираемся, поскольку это последняя и наиболее формализованная версия.

**Следствие.** Всё, что стоит на свингах — BOS, брейкер, митигейшн, дилинг-рейндж,
премиум/дискаунт, — наследует эту неопределённость. Мы кодируем **одну** интерпретацию из
нескольких допустимых. Отрицательный результат бэктеста будет означать «эта интерпретация
не сработала», а **не** «SMC не работает». Положительный — что интерпретация сработала на
этой вселенной и этом окне, не более.

Поэтому размер фрактала (`SMC_SWING_N`, 3 или 5) и режим слома (`body` / `wick`) выносятся
в параметры и свипаются харнессом. Это не тюнинг ради красивой цифры — это измерение
чувствительности вывода к неустранимой неоднозначности источника.

**Второе структурное расхождение.** У автора схема трёхуровневая: контекст (HTF) → поиск
сетапа (MTF) → вход (LTF). Для скальпинга это 4ч+1ч → 5м → 1м; для свинга — неделя → день →
4ч/1ч (`J-timeframes.md`).

Наш движок двухуровневый, и его уровни сдвинуты вверх:

| Горизонт движка | Тренд | Сигнал | Как это у автора |
|---|---|---|---|
| scalp | 4ч | 1ч | оба ТФ — **контекст**; входа (5м/1м) нет вовсе |
| mid | 1д | 4ч | совпадает с его свинг-входом, но над днём у него ещё недельная проверка |

Данных младше 1ч в `data/history` нет, и тянуть их — отдельный проект. Значит **точность
входа автора мы воспроизвести не можем в принципе**. Механизм `defer` — частичная замена:
ожидание отката в зону лимитником даёт часть той же выгоды, что и вход с младшего ТФ,
не требуя новых данных. Это следует прямо сказать в вердикте, а не выдавать полученный
результат за проверку методики автора целиком.

### 6.1 Примитивы (`scripts/smc.mjs`)

Все функции принимают массив закрытых свечей `[{t,o,h,l,c,v,ct}]` по возрастанию `t`.

#### `swings(candles, n)` — свинг-точки
Автор даёт два размера фрактала, оба полностью механические:
- **3-свечной свинг**: центральная свеча, `high` которой строго выше `high` соседей слева
  и справа (свинг-хай); зеркально для лоу. Все три свечи закрыты.
- **5-свечной свинг**: центральная (третья), `high` выше `high` двух свечей слева и двух
  справа. Взаимное расположение крайних свечей значения не имеет. Это **основной** свинг,
  на нём строится структура и определяется BOS.

Цвет свечей не учитывается. Одна свеча может быть одновременно свинг-хаем и свинг-лоу.

`A-structure-range.md` — 3-свечной `[00:45]`, 5-свечной `[02:17]`.

#### `structure(candles)` — рыночная структура
Последовательность HH/HL/LH/LL по 5-свечным свингам.

**Важно для кодирования.** Автор **не различает BOS и CHoCH**: у него есть только «BOS»
(по основной структуре) и «minor BOS» (по внутренней). Он прямо утверждает, что
CHoCH/MSS/MSB — синонимы того же процесса. Искать их как два разных события **нельзя** —
это разошлось бы с источником. `A-structure-range.md`, раздел «Противоречия».

**BOS** = снятие пятисвечного свинга.

**Осторожно: здесь источник расходится сам с собой, и наивное правило будет неверным.**

- Для **брейкера** автор требует закрытия тела за пробитым свингом прямо и однозначно:
  свип без закрепления тела — брейкер не формируется вовсе (`B-blocks.md`).
- Для **рыночной структуры вообще** он, наоборот, дважды прямым текстом **отвергает**
  подтверждение по закрытию тела и в своём предпочтительном методе размечает и свинг, и
  слом **по теням** (`F-liquidity-fakebos.md [02:18]`, `[05:23]`; `H-structure-course.md`).

Поэтому единого правила «слом = закрытие тела» в коде быть не должно. Режим слома —
параметр `SMC_BREAK_MODE` (`body` | `wick`), по умолчанию `wick` (предпочтение автора),
и он свипается харнессом. Для брейкера закрытие тела обязательно **независимо** от режима —
это отдельное, явно заявленное требование.

#### Ложный слом (FAKE BOS)
Автор предупреждает: одного закрытия тела за свингом **недостаточно**. Истинность слома
определяется характером движения — медленный дрейф с накоплением встречной ликвидности
означает ложный слом, агрессивный импульс с образованием имбаланса — истинный.
`F-liquidity-fakebos.md`.

Числового порога «агрессивности» автор не даёт. Прокси **[вывод]**, две проверки, обе
обязательны:
1. размер импульсной ноги, нормированный на ATR(14), `>= 1.5`;
2. сразу после пробоя образовался FVG.

Порог 1.5 выносится в env-параметр и свипается харнессом. Объём как фильтр автор не
использует вовсе — не вводим и мы.

#### `fvg(candles)` — имбалансы
Полная таксономия автора, вся считается из OHLCV:

| Вид | Геометрия |
|---|---|
| FVG (BISI/SIBI) | 3 свечи, `low[i] > high[i-2]` (бычий) — разрыв между тенями |
| IFVG | инвертированный FVG: пробитый и сменивший полярность |
| BPR | наложение бычьего и медвежьего FVG |
| Volume Imbalance | разрыв между телами при пересекающихся тенях |
| Gap | классический разрыв, тени не пересекаются вовсе |

Состояние заполнения: `filledPct`. Уровень **fulfillment** (полное закрытие) — целевой
ориентир; **50% имбаланса** — уровень входа. `C-imbalance-smt.md`.

#### `orderBlocks(candles)` — ордер-блоки
Берём **упрощённую одно-свечную методику** — единственную, помеченную как полностью
формализуемая:

- Бычий OB: закрытая **растущая** свеча, нижняя тень которой сняла ликвидность на продажу
  (обновила предыдущий локальный минимум). Зона = `[low, open]`.
- Медвежий OB: закрытая **падающая** свеча, верхняя тень сняла ликвидность на покупку.
  Зона = `[open, high]`.
- **Обязательно**: следующая свеча должна поглотить манипулятивное движение. Без поглощения
  это не ордер-блок.
- Инвалидация: пробой экстремума зоны.

`B-blocks.md [09:55]`–`[13:01]`.

#### `breaker(candles)` / `mitigation(candles)`
Различаются **только** наличием свипа до слома — это главная находка разбора:

| | Breaker | Mitigation |
|---|---|---|
| Свип до слома структуры | **обязателен** | **отсутствует** |
| Структура | Low1 → LH → Low2 (свип Low1), затем пробой LH с закрытием тела | A → B (провальный свинг) → C (пробой A с закрытием тела) |
| Инвалидация | свип без закрытия тела — брейкер не формируется вовсе | закрытие тела не за свингом; **необратимо** |

Точки брейкера — 5-свечные свинги (сказано явно). Для митигейшн-блока размер фрактала
**не назван** — берём тот же 5-свечной **[вывод]**. `B-blocks.md`.

#### `premiumDiscount(price, range)`
Медиана диапазона. Выше 50% — премиум (зона продаж), ниже — дискаунт (зона покупок).
При бычьем биасе лонг ищется в дискаунте, при медвежьем шорт — в премиуме.
`A-structure-range.md [09:59]`.

**Якорение диапазона** автор задаёт визуально. Берём: последний завершённый импульсный
отрезок между двумя соседними 5-свечными свингами противоположного типа на трендовом ТФ
**[вывод]**. Это главный риск-параметр всего слоя — от него зависит и премиум/дискаунт,
и OTE.

#### `sweep(candles, level)`
Пробой уровня тенью с возвратом закрытия обратно. Противопоставлен слому (закрытие тела за
уровнем).

#### `smtDivergence(alt, btc)`
Один актив обновляет экстремум, коррелят — нет, на синхронизированных по времени свингах.
Слабый актив — в шорт, сильный — в лонг. `C-imbalance-smt.md`.
BTCUSDT уже загружен в харнес — коррелят доступен без новых данных.

### 6.2 Рефайнер: как решение принимается

Четыре обязательных гейта A+ сетапа (`E-aplus-setup.md`), переложенные на наш движок:

| Гейт автора | Реализация | Исход при провале |
|---|---|---|
| 1. Orderflow старшего ТФ | уже есть в v3-focus (`trendDir` на trendTf) | — (сигнала бы не было) |
| 2. Есть цель-магнит | незакрытый FVG или неснятый пул ликвидности впереди цены | `veto` — «нет цели, нет сделки» |
| 3. Тест ранее не смягчённой зоны | OB / брейкер по ходу сделки, ранее не тестированный | `veto` |
| 4. Свип ликвидности перед входом | свип значимого уровня уже произошёл | произошёл → `pass`/`improve`; **не произошёл → `defer`** |

Гейт 4 — источник основной ценности. v3-focus входит по закрытию свечи независимо от того,
собрана ли ликвидность. Автор входит **в момент свипа**. Отсюда `defer`: ждём отката
лимитником в зону имбаланса.

**Уровни при `defer`** (по автору):
- **вход** — начало зоны имбаланса (край), лимитник;
- **стоп** — за вторую свечу формации; ожидаемая ширина 10–30% высоты ренджа;
- **цель** — уровень fulfillment имбаланса старшего ТФ.

**Уровни при `improve`** (вход остаётся рыночным, меняются только стоп и цель):
- стоп переносится за ближайшую структурную точку, если она **ближе** текущего `1.8×ATR`
  (только сужение — расширять стоп запрещено, иначе растёт абсолютный риск);
- цель тянется до ближайшего пула ликвидности, если он **дальше** текущего `RR_CAP 2.5`.

Оба изменения повышают RR. Если ни одно не применимо — исход `pass`.

**TTL отложенного ордера [вывод]:** автор срока жизни лимитника не называет. Берём
`expiryBars = 8` свечей сигнального ТФ и делаем параметром для свипа харнессом.

### 6.3 Генератор: самостоятельный поток

Полный A+ сетап без опоры на индикаторный скор: HTF-биас по структуре (не по EMA) → есть
магнит → цена в зоне интереса в правильной половине диапазона (дискаунт для лонга) →
свип → BOS с закрытием тела → лимитник в имбаланс.

Поток B меряется отдельно и **никогда** не складывается с потоком A в одну цифру.

### 6.4 Чего сознательно НЕ берём

- **Килзоны.** Автор называет окна (азиатская 3:00–8:00, лондонская с 9:00, нью-йоркская
  14:00–17:00, закрытие Лондона 17:00–19:00, часовой пояс UTC+3), но **не обосновывает**
  перенос форекс-сессионной структуры на круглосуточный крипторынок, и час окончания
  лондонской зоны не называет вовсе. `D-killzones-entries.md`. Вводить фильтр, который
  выбросит 3/4 суток без обоснования, — прямой путь к оверфиту. Оставляем как гипотезу
  для отдельного свипа, не в базовой реализации.
- **Частичные тейки (25/25/25/25 или 15/25/30/30).** Автор прямо говорит, что жёсткой схемы
  не существует и он действует ситуативно. Харнес меряет один выход по TP; введение частичных
  фиксаций поменяло бы саму метрику и сделало сравнение с базой невозможным. Отдельная
  итерация после вердикта.
- **Профиль объёма, схемы Wyckoff, скрытая RSI-дивергенция.** Автор сам относит их к
  продвинутому уровню и не даёт операционных определений.

## 6.5 Найденные дефекты

**В проде (`gen-signals.mjs`).** `liquiditySweep` срабатывает на 3 сигналах из 3187 — 0.09%.
Пороги `0.998` / `1.002` при окне в три свечи практически недостижимы. Строка «Smart Money:
снятие ликвидности перед входом» пользователю не показывается никогда. Функция подлежит
либо починке, либо удалению — держать в коде неработающую эвристику, выводимую как признак
качества сигнала, хуже, чем не иметь её вовсе. Замер: `data/backtest/smc-legacy-check.txt`.

**В новом слое (`smc.mjs`, `findFreshPOI`).** Проверка «зона ранее не смягчалась» начинала
скан с `formIdx + 1`, а для ордер-блока это **подтверждающая свеча**, диапазон которой почти
всегда перекрывается с самой зоной. Зона помечалась смягчённой в момент рождения.
Замер на 400 сигналах mid: из 130 случаев «цена входа внутри зоны» 23 (18%) отсекались
исключительно по этой причине. Исправлено; добавлен тест.

Замер там же показал главное: ограничение создаёт не фильтр свежести, а сам факт попадания
цены внутрь зоны — 130 случаев на 3867 валидных зон. Подробности в разделе 9.

Реализация принимается, только если выполнено **всё**:

1. `SMC_MODE=off` → `trades-*.json` бит-в-бит совпадает с текущим базовым реплеем.
2. Lookahead-аудит: 0 нарушений, включая новые SMC-проверки окон.
3. Модуль `smc.mjs` не содержит `fetch` / `readFile` / `writeFile` / `Date.now`.
4. Юнит-тесты на каждый примитив: синтетические свечи с заранее известным ответом
   (ордер-блок есть / нет, FVG закрыт / открыт, свип был / не был).
5. Отчёт по разделу 5 сгенерирован и включает контрфактические цифры по отменённым.
6. Вердикт формулируется на **суммарном netPnl и дельте на пересечении**, а не на avgNetR.

## 9. Результаты эксперимента

Все прогоны — вселенная top-100 (101 символ), окно 2021-07 … 2026-07, горизонты scalp+mid,
lookahead-аудит PASS. Набор сигналов во всех SMC-армах идентичен базовому (3352 записи)
по построению из раздела 5.1.

| Конфигурация | взято | поток | дельта на пересечении | Σ netR |
|---|---|---|---|---|
| **база** v3-focus | 3352 | — | — | **+373.6** |
| все гейты `2,3,4` | 338 | −89.9% | −32.4 | +18.2 |
| без гейта 3 `2,4` | 3283 | −2.1% | −32.4 | +328.9 |

Плюс два контроля из раздела 5.3 (`ctl14` +723%, `ctl14rr` +738% против базовых +1219% —
оба хуже).

### Разложение по каналам (на почти полном потоке, арм `2,4`)

| Канал | n | дельта | на сделку |
|---|---|---|---|
| `improve` — стоп и цель по структуре | 246 | **+10.9** | +0.044 |
| `defer` — отложенный лимитник | 65 | **−43.3** | −0.67 |
| `veto` — оставшееся (нет магнита) | 53 | −13.8 | −0.26 |

### Вывод

**Рефайнер не работает, и причина архитектурная.** Снятие «слишком строгого» гейта 3
возвращает поток (−2.1% вместо −89.9%), но дельта не меняется вовсе: те же −32.4. То есть
дело не в настройке условия.

Корень: v3-focus входит **по закрытию импульсной свечи** (RSI 50–65, ADX ≥ 35, цена за EMA50,
анти-чейз), SMC — **на откате в зону**. Замер на 400 сигналах mid: из 3867 валидных зон
интереса цена входа попадает внутрь лишь в 130 случаях. Пересечение двух геометрий почти
пусто по построению, и подбором порогов это не лечится.

Отложенный вход убыточен по конкретной механике, подтверждённой на графиках: структурный
стоп ставится по краю зоны и потому ближе базового; откат, которого лимитник ждал, доходит
до зоны, заполняет ордер и **тем же движением выбивает стоп**, после чего цена уходит к цели
без позиции. Примеры: NFPUSDT 4h (+2.48 у базы против −1.04 у слоя), CHRUSDT 1h (+2.46
против −1.12).

Вето отменяет не мусор, а рабочие сделки: контрфакт по 2998 отменённым сигналам +324.4,
средний +0.108. На графиках это учебные momentum-шорты (AAVE, AVAX, май 2022, по +2.49R).

**Единственный неотрицательный канал — `improve`** (+10.9 на 246 сделках). Каналы не
пересекаются, а `as-is` даёт ноль по построению, поэтому конфигурация «только improve»
дала бы ровно `373.6 + 10.9 = 384.5`, то есть +2.9% к базе.

**Но это ноль.** СКО поканальной дельты 2.468 на сделку при среднем +0.044:
`t = 0.28`, 95% ДИ суммы `[−64.9, +86.8]`. Заявлять +2.9% выигрышем означало бы выдать шум
за результат — ровно та ошибка, от которой защищает раздел 5.

Итог: **измеримой пользы не показал ни один канал.** Два уверенно отрицательны, третий
статистически пуст. Гипотеза структурного стопа не опровергнута — она не проверена за
недостатком выборки; вернуться к ней имеет смысл на большем потоке (например, вместе
с генератором из раздела 2, потока B).

### Чего результат НЕ означает

Не «SMC не работает». Проверена **одна архитектура** (слой поверх готовых сигналов
v3-focus) и **одна интерпретация** правил автора — того самого, который размечает свинги
«на глаз» и даёт три несовпадающих определения слома (раздел 6.0). Вывод строго такой:
эта конструкция не даёт эджа на этой вселенной и в этом окне.
